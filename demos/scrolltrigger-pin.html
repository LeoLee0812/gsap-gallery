pin · 让页面停下来讲故事

滚到某一屏时页面「卡住」不动，你继续滚，内容在原地变化，变完才放行继续往下。 苹果产品页大量用这个。
pin 的本质：把元素临时改成 fixed，同时在原位置塞一个等高的占位块， 让后面的内容不至于往上跳。这两件事 GSAP 都替你做了。

↓

① 基础 pin + scrub

下面这一屏会被钉住 3 屏的滚动距离。期间数字和文字随滚动变化，滚完才继续往下走。

01
页面被钉住了，继续往下滚
ScrollTrigger.create({
  trigger: ".pinSection",   // 触发区：高度决定「钉多久」
  start: "top top",
  end: "bottom bottom",
  pin: ".pinBox",          // 真正被钉住的元素
  scrub: 0.8,
  animation: tl
});

// 关键：外层 .pinSection 高 300vh，内层 .pinBox 高 100vh
// 多出来的 200vh 就是「钉住期间可以滚的距离」
pin 时长怎么算：被钉住的时长 = 触发区高度 − 视口高度。 想钉得久一点，就把外层容器加高。这是最常见的疑惑点——很多人以为 pin 有个「时长」参数，其实是用高度控制的。

② pinSpacing：那块占位空间要不要留

左右两个独立滚动容器，配置完全一样，只有 pinSpacing 不同。 在容器里滚一滚，注意绿色块被钉住后，后面的内容表现有什么差别。

③ pin 的经典应用：假横向滚动

你正常往下滚鼠标，内容却在横向移动。原理就是 pin 住整屏，把纵向滚动进度映射成横向位移。

// 横向滚动的标准写法
const track = document.querySelector(".hTrack");

gsap.to(track, {
  // 往左移动「内容总宽 − 视口宽」这么多
  x: () => -(track.scrollWidth - window.innerWidth),
  ease: "none",
  scrollTrigger: {
    trigger: ".hSection",
    start: "top top",
    end: "bottom bottom",
    pin: ".hPin",
    scrub: 1,
    // 窗口尺寸变化时重新计算上面那个函数式的 x 值
    invalidateOnRefresh: true
  }
});
⚠️ pin 的四个高频坑：
① 不要动被 pin 的元素本身（它的 transform 已经被 ScrollTrigger 占用），要动就动它的子元素。
② 不要把 ScrollTrigger 放在时间轴内部的子 tween 上，只能放在顶层 tween 或整条 timeline 上。
③ 图片、字体加载完会改变布局，导致 pin 的位置算错。在资源加载完后调 ScrollTrigger.refresh()。
④ 被 pin 元素的祖先不能有 transform / filter——CSS 规范里这会让 fixed 定位失效，pin 会直接乱掉。这是最难排查的一个。
