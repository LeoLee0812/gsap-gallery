quickTo / quickSetter · 高频更新的正确写法

鼠标跟随、拖拽、滚动联动这类每帧都要改同一个属性的场景，如果每次都写 gsap.to()， 就是每帧创建一个全新的 tween 对象——几百个一次性对象往 GC 里灌。 在两个方框里移动鼠标，看右下角的实例计数差多少。

同样的效果，两种写法在数量上来之后差距会非常明显。切换写法，在方框里快速画圈，观察右侧 FPS。 （现代浏览器很能扛，如果你机器很强可能都不掉帧——那也说明了另一件事：不要为了没测出来的性能问题过度优化。）

// ❌ 错误：每次 mousemove 创建一个新 tween，一秒钟能造出上百个一次性对象
document.addEventListener("mousemove", (e) => {
  gsap.to(cursor, { x: e.clientX, y: e.clientY, duration: 0.4 });
});

// ✅ 正确：quickTo 只创建一次，返回一个函数，之后每帧只是更新目标值
const xTo = gsap.quickTo(cursor, "x", { duration: 0.4, ease: "power3" });
const yTo = gsap.quickTo(cursor, "y", { duration: 0.4, ease: "power3" });

document.addEventListener("mousemove", (e) => {
  xTo(e.clientX);   // 只是改目标值，不新建对象
  yTo(e.clientY);
});

// ✅ 完全不需要补间（要立刻跟手、没有延迟感）时，用 quickSetter 更省
const setX = gsap.quickSetter(cursor, "x", "px");
setX(e.clientX);   // 直接写入，零补间开销

三者怎么选：
· quickTo —— 需要平滑跟随（有阻尼、有延迟感）。自定义光标、磁吸元素、视差层。
· quickSetter —— 要求完全跟手、不能有一帧延迟。拖拽中的元素、精确对齐的辅助线。
· gsap.to —— 一次性的、非高频的动画。点击展开、入场退场。这才是它该待的地方。

另一个常被忽略的点：quickTo 返回的函数还能接收第二个参数覆盖 duration， 比如 xTo(200, 0.1) 就是这一次用 0.1 秒——做「速度自适应」的跟随很好用。
