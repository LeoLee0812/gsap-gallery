Observer · 统一手势输入

鼠标滚轮、触控板双指、手机滑动、鼠标拖拽、键盘方向键——原生要写五套监听，还要各自处理兼容和节流。 Observer 把它们归一成同一套回调，你只关心「往哪个方向、动了多少」。

事件日志
Observer.create({
  target: "#pad",
  // 想监听哪几类输入就写哪几类，全都归一到同一批回调
  type: "wheel,touch,pointer",

  // 通用回调：任何输入变化都进这里
  onChange: (self) => {
    // self.deltaX / deltaY 是本次位移，velocityX / velocityY 是速度
    gsap.to("#puck", { x: "+=" + self.deltaX, y: "+=" + self.deltaY });
  },

  // 方向回调：只在「明确朝某个方向」时触发一次，做整屏翻页最合适
  onUp:    () => nextSlide(),
  onDown:  () => prevSlide(),
  onLeft:  () => {}, onRight: () => {},

  // 两次方向触发之间的冷却时间，防止一次滑动被识别成好几次
  tolerance: 10,
  // 阻止页面本身跟着滚动
  preventDefault: true
});

Observer 和 ScrollTrigger 的分工：ScrollTrigger 关心「页面滚到哪了」， Observer 关心「用户做了什么输入动作」——后者不依赖页面真的有滚动条。 所以全屏一页一屏的站、锁死滚动的引导流程、自定义手势轮播，都得用 Observer 而不是 ScrollTrigger。
onStop 在输入停止后触发，用来做「松手后归位/吸附」；tolerance 调大能过滤掉触控板的细碎抖动。
