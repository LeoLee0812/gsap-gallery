GSAP 在 React / Next.js 里的正确用法

React 和 GSAP 的核心矛盾只有一句话：React 会反复重新渲染和卸载组件，而 GSAP 的动画是挂在真实 DOM 上的。 处理不好就是内存泄漏、动画重复叠加、控制台一堆警告。 官方给了 useGSAP() 这个 hook，把这些全解决了。

安装

npm install gsap @gsap/react

@gsap/react 是独立的包，只有几百行，提供 useGSAP() 一个 hook。 GSAP 本体和所有插件现在全部免费，直接从公共 npm 装即可，不需要 .npmrc、不需要 auth token、不需要私有源 ——网上那些教你配私有 registry 的老教程可以忽略了。

核心写法

// components/Hero.jsx
import { useRef } from "react";
import gsap from "gsap";
import { useGSAP } from "@gsap/react";

// 注册一次即可，通常放在应用入口
gsap.registerPlugin(useGSAP);

export default function Hero() {
  const container = useRef(null);

  useGSAP(() => {
    // 这里面的所有 GSAP 动画都会被自动记录
    // 组件卸载时统统 revert（撤销内联样式 + kill 动画 + 清理 ScrollTrigger）
    gsap.from(".title", { y: 40, opacity: 0, duration: 0.8 });
    gsap.from(".card", { y: 30, opacity: 0, stagger: 0.1 });
  }, { scope: container });   // ← scope 是关键，见下方

  return (
    <div ref={container}>
      <h1 className="title">标题</h1>
      <div className="card">卡片</div>
    </div>
  );
}

为什么必须传 scope

没有 scope 时，".card" 这个选择器会匹配整个页面上所有 .card—— 包括别的组件里的、包括同一个组件渲染多份时其他实例里的。 传了 scope 之后，选择器只在这个 ref 容器内部查找。

这也是为什么在 React 里能安心用类选择器而不必给每个元素都建 ref。 需要单个元素的精确引用时才用 ref，批量元素用 scope + 类选择器更省事。

依赖数组与重新执行

useGSAP(() => {
  gsap.to(".box", { x: endX });
}, {
  dependencies: [endX],     // 和 useEffect 一样，endX 变化时重新执行
  scope: container,
  revertOnUpdate: true     // 重新执行前，先把上一轮的动画完全撤销
});
revertOnUpdate 很容易被忽略。不加它，依赖变化时会在旧动画留下的内联样式之上再叠一层新动画， 元素会越跑越偏。加上之后每次都从干净状态重新开始。

事件回调里创建动画：contextSafe

useGSAP 只能自动管理它回调函数体内同步创建的动画。 点击、hover 这类事件里创建的动画属于「之后才发生」，需要用 contextSafe 包一层， 它返回的函数才会被纳入清理范围。 

const { contextSafe } = useGSAP({ scope: container });

// 包一层，卸载后调用会安全地什么都不做，而不是报错
const handleClick = contextSafe(() => {
  gsap.to(".box", { rotation: "+=360", duration: 0.6 });
});

return <button onClick={handleClick}>转一圈</button>;

常见错误对照

❌ 用 useEffect 但忘了清理 
useEffect(() => {
  gsap.to(".box", { x: 100, scrollTrigger: ".box" });
  // 组件卸载后，这个 ScrollTrigger 还挂在页面上监听滚动 → 内存泄漏
  // 路由来回切几次就攒了一堆僵尸监听器
}, []);
✅ useGSAP 自动处理 
useGSAP(() => {
  gsap.to(".box", { x: 100, scrollTrigger: ".box" });
}, { scope: container });
// 卸载时 ScrollTrigger 自动 kill，内联样式自动 revert
❌ 在 Next.js 服务端组件里用 
// app/page.jsx —— 默认是服务端组件
import gsap from "gsap";   // 报错：document is not defined
✅ 加 "use client" 
"use client";   // ← 必须放在文件第一行

import gsap from "gsap";
import { useGSAP } from "@gsap/react";
// GSAP 操作真实 DOM，只能在客户端跑
❌ 用 state 驱动每一帧 
const [x, setX] = useState(0);
// 每帧 setState → 每帧触发 React 重渲染 → 卡成幻灯片
onMouseMove={e => setX(e.clientX)}
✅ 让 GSAP 直接操作 DOM，绕开 React 渲染 
const xTo = useRef();

useGSAP(() => {
  // quickTo 只创建一次，之后每帧只是改目标值
  xTo.current = gsap.quickTo(".cursor", "x", { duration: 0.4 });
}, { scope: container });

// 完全不经过 React 的 state，零重渲染
onMouseMove={e => xTo.current(e.clientX)}

速查表

你要做的事怎么写
组件挂载时播一次入场useGSAP(() => {...}, { scope: ref })
某个 state 变化时重播{ dependencies: [state], revertOnUpdate: true }
点击 / hover 时触发const fn = contextSafe(() => {...})
需要控制动画（暂停/倒放）把 timeline 存进 useRef，不要用 state
高频更新（鼠标跟随）gsap.quickTo() 存进 ref，绕开 React 渲染
Next.js App Router文件顶部加 "use client"
列表项各自的动画子组件内各自 useGSAP + 各自的 scope
手动清理某个动画useGSAP 回调里 return () => {...}
最后一条经验：不要试图用 React 的 state 来「驱动」动画。 正确的心智模型是——React 负责渲染 DOM 结构，GSAP 直接接管这些 DOM 节点的视觉表现，两者井水不犯河水。 一旦你开始用 state 存动画进度、用 setState 推进每一帧，就说明用错了。
