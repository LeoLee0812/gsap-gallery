matchMedia · 响应式动画与无障碍降级

拖动浏览器窗口宽度看动画自己换一套。这是 GSAP 处理响应式的官方方式： 不同断点写不同动画，切换时旧的自动清理干净，不用手写 kill。

(min-width: 900px) 桌面
(600px ~ 899px) 平板
(max-width: 599px) 手机

模拟系统「减少动态效果」： 
// 一个 mm 实例管理所有断点，revert() 一次性清理全部
const mm = gsap.matchMedia();

mm.add({
  isDesktop: "(min-width: 900px)",
  isTablet:  "(min-width: 600px) and (max-width: 899px)",
  isMobile:  "(max-width: 599px)",
  // 系统层面的无障碍偏好，和屏幕宽度一样可以当条件用
  reduce:    "(prefers-reduced-motion: reduce)"
}, (ctx) => {
  const { isDesktop, isTablet, isMobile, reduce } = ctx.conditions;

  // 开了减少动态效果：只做最朴素的淡入，不位移不旋转
  if (reduce) {
    gsap.fromTo(".card", { opacity: 0 }, { opacity: 1, duration: 0.4 });
    return;
  }

  gsap.timeline({ repeat: -1, yoyo: true })
    .from(".card", {
      // 同一份代码，参数按断点取不同值
      y: isDesktop ? 90 : isTablet ? 50 : 24,
      rotate: isDesktop ? 180 : isMobile ? 0 : 90,
      scale: isMobile ? 0.85 : 0,
      stagger: isDesktop ? 0.09 : 0.04,
      duration: isMobile ? 0.35 : 0.7,
      ease: "back.out(1.6)"
    });

  // 返回的函数在断点切走时自动执行，用来做额外清理
  return () => console.log("离开这个断点，动画已自动回滚");
});

为什么必须用 matchMedia 而不是自己监听 resize： 断点切换时 GSAP 会把上一套动画写进元素的内联样式全部 revert 掉， 不会出现「手机上还残留着桌面动画留下的 transform」这类脏状态。
prefers-reduced-motion 不是可选项——前庭功能障碍的用户看到大幅位移和旋转会真的头晕。 把它当成一个断点写进 matchMedia，是成本最低的无障碍处理。
