InertiaPlugin · 松手之后的那一段

拖拽本身只解决「跟手」，真正决定手感的是松手之后：是戛然而止，还是带着速度滑一段再自然停下。 Inertia 会读取你松手瞬间的速度，算出一条符合物理直觉的减速轨迹——这就是原生 App 滑动列表的手感来源。

① 纯惯性滑行
松手后按当时速度继续滑，逐渐减速停下。甩得越猛滑得越远，完全由速度决定。

② 惯性 + 网格吸附
滑行结束前，会把落点吸到最近的 50px 网格上——既保留了惯性，又保证最终位置整齐。

③ 惯性 + 边界回弹
超出边界时会被拉回来，带一点橡皮筋回弹。iOS 列表滑到头的那种感觉。

④ 实战：惯性横向列表（拖动 + 甩动）
和手机上的横向卡片列表一个手感：拖到哪、甩多远，都由速度和边界共同决定。
gsap.registerPlugin(Draggable, InertiaPlugin);

Draggable.create("#puck", {
  type: "x,y",
  bounds: ".field",

  // 只需这一个开关，松手后的惯性滑行就有了
  inertia: true,

  // snap 定义「滑行的落点」怎么修正，而不是拖动过程中就吸附
  snap: {
    x: value => gsap.utils.snap(50, value),
    y: value => gsap.utils.snap(50, value)
  },

  // 甩出边界时的回弹力度；0.6 比较接近 iOS 的手感
  edgeResistance: 0.65,

  onThrowUpdate: function() { /* 惯性滑行的每一帧 */ },
  onThrowComplete: function() { /* 完全停下 */ }
});

// 也能脱离拖拽，直接对任意属性做惯性补间：
gsap.to(box, { inertia: { x: { velocity: 800, end: 400 } } });

inertia: true 和 snap 的关系常被搞混：snap 修正的是惯性滑行的最终落点， 不是拖动过程中的实时位置——所以拖的时候依然是自由的，只在松手后才「归位」。这正是好手感的关键。
edgeResistance（0~1）控制拖出边界时的阻力：0 = 毫无阻力随便拖出去，1 = 硬边界完全拖不动， 0.6 左右最接近原生 App。
InertiaPlugin 以前是 Club GSAP 付费插件，现在免费，可以放心用于商业项目。
