ScrollTrigger.batch

60 张卡片如果各写一个入场动画，就是 60 条互不相干的 tween，进场时间参差、性能也差。 batch 会把「同一时间窗口内进入视口的元素收集成一批」，再统一用一条带 stagger 的动画处理—— 既有整齐的级联感，又只创建一条 tween。
往下滚，右上角能看到每批实际收进了几张。

↓
卡片列表（滚动触发批量入场，往回滚会重置）
// batch 的回调签名和普通 ScrollTrigger 不同：收到的是「一批元素的数组」
ScrollTrigger.batch(".card", {
  start: "top 88%",

  // elements 是这一批同时进入视口的元素；triggers 是对应的 ScrollTrigger 实例
  onEnter: (elements) => gsap.to(elements, {
    opacity: 1, y: 0, scale: 1,
    stagger: 0.08, duration: 0.55, ease: "power3.out",
    overwrite: true
  }),

  // 往回滚出顶部时复位，这样再滚下来还能看到动画
  onLeaveBack: (elements) => gsap.set(elements, { opacity: 0, y: 40, scale: 0.92 }),

  interval: 0.12,   // 收集窗口：0.12 秒内进场的算同一批
  batchMax: 6       // 一批最多 6 个，满了立刻发车、开下一批
});

什么时候该用 batch：列表、瀑布流、卡片墙——凡是「一大批同类元素要滚动入场」的场景。
batchMax 调大调小的区别：调小（3）→ 每批少、发车频繁、级联更细碎；调大（12）→ 一次涌入更多，气势更足但整齐感下降。 在上面的按钮里切换试试。
注意：batch 不接受 trigger（目标本身就是触发器），也不接受 scrub、toggleActions、snap 这类需要绑定单条动画的选项。
