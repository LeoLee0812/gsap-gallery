GSAP 在 Vue / Nuxt / Svelte 里的写法

React 有官方的 useGSAP hook 兜底，其他框架没有——但要做的事完全一样： 在挂载后创建动画、在卸载前清理干净、把选择器限制在组件内部。 只是换成各自框架的生命周期钩子而已。

基础：onMounted 创建，onUnmounted 清理

<!-- Hero.vue -->
<script setup>
import { ref, onMounted, onUnmounted } from "vue";
import gsap from "gsap";

const container = ref(null);
let ctx;

onMounted(() => {
  // gsap.context 是非 React 框架里的清理利器
  // 第二个参数就是 scope，选择器只在容器内部查找
  ctx = gsap.context(() => {
    gsap.from(".title", { y: 40, opacity: 0, duration: 0.8 });
    gsap.from(".card", { y: 30, opacity: 0, stagger: 0.1 });
  }, container.value);
});

onUnmounted(() => {
  // 一行撤销全部：kill 动画 + 移除内联样式 + 清理 ScrollTrigger
  ctx?.revert();
});
</script>

<template>
  <div ref="container">
    <h1 class="title">标题</h1>
    <div class="card" v-for="n in 3" :key="n">卡片 {{ n }}</div>
  </div>
</template>

响应数据变化时重播

import { watch } from "vue";

watch(activeTab, (val) => {
  // 数据变了就重新播，别忘了 overwrite 防止叠加
  gsap.to(".indicator", {
    x: val * 120,
    duration: 0.4,
    ease: "power2.out",
    overwrite: "auto"
  });
});

v-for 列表：等 DOM 更新完再动画

import { nextTick } from "vue";

async function addItem() {
  items.value.push(newItem);
  // 必须等 Vue 把新节点渲染进 DOM，否则选择器选不到
  await nextTick();
  gsap.from(".item:last-child", { scale: 0, opacity: 0, duration: 0.4 });
}

配合 Vue 内置的 Transition 组件

Vue 的 <Transition> 提供了 JS 钩子，可以把 GSAP 接进去， 这样进出场时机由 Vue 管理，动画本身由 GSAP 实现。done 回调一定要调用， 否则 Vue 不知道动画结束了，元素不会被正确移除。 

<Transition
  :css="false"
  @enter="onEnter"
  @leave="onLeave"
>
  <div v-if="show" class="modal">…</div>
</Transition>

// ---
function onEnter(el, done) {
  gsap.from(el, { scale: 0.9, opacity: 0, duration: 0.35, onComplete: done });
}
function onLeave(el, done) {
  gsap.to(el, { scale: 0.95, opacity: 0, duration: 0.25, onComplete: done });
}

Nuxt 的额外问题：SSR

Nuxt 默认服务端渲染，而 GSAP 需要真实的 window 和 document。 在服务端执行 GSAP 代码会直接报错。所有 GSAP 调用都必须在客户端生命周期里。

❌ 在 setup 顶层直接跑 
<script setup>
import gsap from "gsap";
import ScrollTrigger from "gsap/ScrollTrigger";

// 服务端也会执行这行 → window is not defined
gsap.registerPlugin(ScrollTrigger);
</script>
✅ 放进 onMounted，并从 /dist 引插件 
<script setup>
import gsap from "gsap";
// 注意从 gsap/dist/ 引入，这个路径是 UMD 版本，兼容性更好
import { ScrollTrigger } from "gsap/dist/ScrollTrigger";

const container = ref(null);
let ctx;

onMounted(() => {
  gsap.registerPlugin(ScrollTrigger);   // 只在客户端注册

  ctx = gsap.context(() => {
    gsap.to(".panel", {
      y: -100,
      scrollTrigger: { trigger: ".panel", scrub: 1 }
    });
  }, container.value);
});

onUnmounted(() => ctx?.revert());
</script>

路由切换后 ScrollTrigger 位置错乱

Nuxt 的页面切换是客户端路由，DOM 换了但 ScrollTrigger 记录的还是旧页面的位置。 切换后要手动 refresh 一次。 

const router = useRouter();

router.afterEach(() => {
  // 等新页面 DOM 渲染完再刷新，否则量到的还是旧高度
  nextTick(() => ScrollTrigger.refresh());
});

做成插件全局注册

// plugins/gsap.client.js —— 文件名带 .client 表示只在客户端跑
import gsap from "gsap";
import { ScrollTrigger } from "gsap/dist/ScrollTrigger";

gsap.registerPlugin(ScrollTrigger);

export default defineNuxtPlugin(() => ({
  provide: { gsap, ScrollTrigger }
}));

// 组件里：const { $gsap } = useNuxtApp();

基础：onMount 返回清理函数

Svelte 的 onMount 有个很方便的特性：它返回的函数会在组件销毁时自动执行， 所以不需要单独写 onDestroy。 

<script>
  import { onMount } from "svelte";
  import gsap from "gsap";

  let container;

  onMount(() => {
    const ctx = gsap.context(() => {
      gsap.from(".title", { y: 40, opacity: 0, duration: 0.8 });
      gsap.from(".card", { y: 30, opacity: 0, stagger: 0.1 });
    }, container);

    // onMount 返回的函数 = 组件销毁时执行，比 React 还省事
    return () => ctx.revert();
  });
</script>

<div bind:this={container}>
  <h1 class="title">标题</h1>
  {#each items as item}
    <div class="card">{item}</div>
  {/each}
</div>

SvelteKit 的 SSR 处理

import { browser } from "$app/environment";

// 方式一：条件判断
if (browser) {
  gsap.registerPlugin(ScrollTrigger);
}

// 方式二：动态导入，插件代码根本不会进服务端 bundle
onMount(async () => {
  const { ScrollTrigger } = await import("gsap/dist/ScrollTrigger");
  gsap.registerPlugin(ScrollTrigger);
  // …动画代码
});

Svelte 的 action：把动画封装成可复用指令

这是 Svelte 独有的优雅之处。action 天生带 destroy 钩子， 非常适合把「元素进入视口就淡入」这类通用动画封装起来，用 use: 一行挂上去。 

// lib/actions/fadeIn.js
import gsap from "gsap";
import { ScrollTrigger } from "gsap/dist/ScrollTrigger";

export function fadeIn(node, params = {}) {
  const tween = gsap.from(node, {
    y: params.y ?? 40,
    opacity: 0,
    duration: params.duration ?? 0.7,
    scrollTrigger: { trigger: node, start: "top 85%" }
  });

  return {
    // 元素销毁时自动调用
    destroy() {
      tween.scrollTrigger?.kill();
      tween.kill();
    }
  };
}

// 用法：一行搞定，还能传参
// <div use:fadeIn>…</div>
// <div use:fadeIn={{ y: 80, duration: 1 }}>…</div>

Svelte 5 的 runes 写法

<script>
  let container;

  // $effect 相当于 onMount + 依赖追踪，返回值同样用于清理
  $effect(() => {
    const ctx = gsap.context(() => {
      gsap.from(".card", { y: 30, opacity: 0, stagger: 0.1 });
    }, container);

    return () => ctx.revert();
  });
</script>

四条通用原则（任何框架都成立）

原则做法不做的后果
1. 等 DOM 就绪再创建动画 onMounted / onMount / $effect 选择器选不到元素，动画静默失败
2. 用 gsap.context 包住 gsap.context(fn, scopeElement) 选择器泄漏到别的组件；无法一次性清理
3. 销毁时 revert ctx.revert() ScrollTrigger 变僵尸监听器，内存泄漏
4. SSR 框架只在客户端跑 .client.js / if (browser) / 动态 import 构建或首屏直接报 window is not defined

gsap.context 到底做了什么

这是非 React 框架里最重要的一个 API，它做两件事： 

const ctx = gsap.context(() => {
  // ① 记录：这个回调里创建的所有动画、ScrollTrigger、Draggable 都被登记在案
  gsap.to(".box", { x: 100 });
  ScrollTrigger.create({ /* … */ });
}, scopeElement);
// ② 限定作用域：上面的 ".box" 只在 scopeElement 内部查找

ctx.revert();
// 一次性撤销：kill 所有动画 + 移除 GSAP 写入的内联样式 + 清理所有插件实例
// 元素回到 GSAP 从没碰过它的状态

ctx.kill();
// 只 kill 动画，保留当前的视觉状态（元素停在原地不回弹）
revert 和 kill 的区别经常被搞错：
· revert() —— 撤销一切，元素回到动画开始前的样子。组件卸载时用这个。
· kill() —— 只停止动画，元素停在当前位置。想让元素保持当前状态时用这个。

Astro / 原生 Web Components

// Astro：脚本默认就在客户端跑，但要注意 View Transitions
// astro:page-load 每次页面切换后都会触发（含首次加载）
document.addEventListener("astro:page-load", () => {
  gsap.from(".card", { y: 30, opacity: 0, stagger: 0.1 });
  ScrollTrigger.refresh();
});

// Web Components：用自定义元素自己的生命周期
class MyCard extends HTMLElement {
  connectedCallback() {
    this.ctx = gsap.context(() => {
      gsap.from(this.querySelector(".inner"), { opacity: 0 });
    }, this);
  }
  disconnectedCallback() {
    this.ctx.revert();
  }
}
