overwrite · 两条动画抢同一个元素

「为什么我的元素动到一半突然跳了一下」「为什么快速划过卡片后它卡在中间状态」—— 答案基本都是两条 tween 在同时改同一个属性。overwrite 决定新来的那条怎么处理旧的。
下面三个格子里，会先启动一条「向右 + 变红」的长动画，0.6 秒后再插入一条「只改 y」的动画。

overwrite: false　（默认）
谁也不杀谁，两条同时跑。改的是不同属性时没问题； 改同一个属性就会互相打架，画面抖动。
overwrite: "auto"　（推荐）
只杀掉冲突的那几个属性，不相干的属性照常跑。 这里 x 和 backgroundColor 会继续，只有重叠的属性被接管。
overwrite: true
把这个元素上所有正在跑的动画全杀掉，不管冲不冲突。 最粗暴，也最可预测——所以 hover 这类频繁打断的场景反而适合它。
真实场景：快速划过卡片
鼠标飞快地在三张卡片上来回扫。不做 overwrite 处理的那张会卡在中间状态—— 因为进场动画还没跑完，离场动画就叠上来了，两条都在改 scale。

// 场景：hover 进出非常频繁，进场动画还没播完就要播离场

// ❌ 不处理：两条 tween 同时改 scale，元素会卡在诡异的中间值
card.addEventListener("mouseenter", () => gsap.to(card, { scale: 1.1, duration: 0.4 }));
card.addEventListener("mouseleave", () => gsap.to(card, { scale: 1,   duration: 0.4 }));

// ✅ 方案一：overwrite "auto"，新 tween 自动接管冲突属性
gsap.to(card, { scale: 1.1, duration: 0.4, overwrite: "auto" });

// ✅ 方案二：手动杀掉这个元素上所有动画再开新的
gsap.killTweensOf(card);
gsap.to(card, { scale: 1.1, duration: 0.4 });

// ✅ 方案三（最优雅）：hover 类交互直接用 quickTo，天然不会堆积
const scaleTo = gsap.quickTo(card, "scale", { duration: 0.4, ease: "power2.out" });
card.onmouseenter = () => scaleTo(1.1);
card.onmouseleave = () => scaleTo(1);

为什么默认是 false 而不是 auto：因为 GSAP 不想替你做决定。 很多正常场景就是需要多条 tween 同时作用于一个元素的不同属性（一条管位置、一条管颜色、一条管旋转）， 默认全杀会把这些正常用法搞坏。
什么时候一定要设 overwrite：凡是同一个属性可能被反复重新触发的地方—— hover 进出、拖拽跟随、滚动方向切换、按钮连点。
还有个 immediateRender 的坑：两条 from() 作用于同一元素同一属性时， 后一条会在创建瞬间就把元素设成它的起始值，导致第一条的效果看不见。 这时给后一条加 immediateRender: false。
